==============================================================================
 AFK MANAGER - EINRICHTUNG
==============================================================================

Der AFK Manager hält mehrere Minecraft-Accounts rund um die Uhr auf einem
Server online (Java und Bedrock). Du steuerst alles über ein Web-Dashboard im
Browser und optional über Discord (Befehle, Benachrichtigungen, Chat-Spiegel).

Der Manager meldet sich nach Kicks oder Server-Neustarts automatisch wieder an,
und zwar nacheinander von oben nach unten in der Account-Liste.


------------------------------------------------------------------------------
 0. WAS DU BRAUCHST
------------------------------------------------------------------------------

 - Einen Rechner, der dauerhaft läuft: Raspberry Pi, Mini-PC, Server oder zum
   Ausprobieren einfach dein normaler PC/Laptop.
 - Node.js 22 oder neuer: https://nodejs.org
   Prüfen mit:  node -v
   (Auf Linux/Raspberry Pi ist die Version aus dem Paketmanager manchmal zu alt.)
 - Minecraft-Accounts mit Microsoft-Konto.
   WICHTIG: Aktiviere bei jedem dieser Microsoft-Konten die
   Zwei-Faktor-Authentifizierung (https://account.microsoft.com/security).
   Ohne 2FA scheitert der Login-Code-Ablauf bei manchen Konten mit der Meldung
   "device_code has already been used".
 - git (Linux: sudo apt install git, Windows: https://git-scm.com)
 - Optional: ein Discord-Server, auf dem du einen Bot oder Webhooks anlegen
   darfst.


------------------------------------------------------------------------------
 1. HERUNTERLADEN
------------------------------------------------------------------------------

Öffne ein Terminal (Windows: PowerShell) in dem Ordner, in den der Manager soll
(z.B. dein Benutzerordner), und führe aus:

   git clone https://github.com/nilsmovie/afk-manager.git
   cd afk-manager

Damit entsteht der Ordner "afk-manager" mit allen Programmdateien. Beim
Betrieb kommen weitere Dateien dazu:
   accounts.json, accounts.backup.json   (deine Minecraft-Accounts)
   users.json, users.backup.json         (Dashboard-Benutzer, Passwörter gehasht)
   servers.json, verbindungen.json       (nur bei mehreren Servern, Abschnitt 5b)
   accounts.vor-mehrserver.json          (einmalige Sicherung, Abschnitt 5b)
   audit.log                             (Protokoll, Abschnitt 10)
   .env                                  (deine Einstellungen)
Diese Dateien sind privat - siehe Abschnitt 9.


------------------------------------------------------------------------------
 2. INSTALLATION
------------------------------------------------------------------------------

Im Ordner afk-manager:

   npm install

Das lädt alle Abhängigkeiten herunter und dauert ein paar Minuten.

Schlägt die Installation bei "raknet-native" fehl, siehe Abschnitt 10,
Punkt "npm install bricht ab". Das betrifft nur die Bedrock-Unterstützung.


------------------------------------------------------------------------------
 3. EINSTELLUNGEN (.env)
------------------------------------------------------------------------------

   Windows:      copy .env.example .env
   Linux / Mac:  cp .env.example .env

Öffne die neue Datei ".env" mit einem Texteditor und trage mindestens ein:

   DASHBOARD_PASSWORD   Dein Passwort fürs Dashboard (Abschnitt 4).
   DASHBOARD_OWNER      Dein Benutzername fürs Dashboard (leer = admin).
   MC_SERVER_HOST       Adresse deines Minecraft-Servers, z.B. play.beispiel.net
   MC_SERVER_PORT       Meist 25565
   MC_BEDROCK_PORT      Meist 19132 (nur für Bedrock-Accounts)

In der .env.example steht bei MC_SERVER_HOST schon clashsmp.de. Löschst du den
Eintrag, startet kein Account (der Manager sagt das im Log, im Dashboard und
in Discord). Alle Einstellungen sind in der .env.example erklärt.


------------------------------------------------------------------------------
 4. STARTEN UND ERSTER LOGIN
------------------------------------------------------------------------------

   node server.js

Öffne im Browser:   http://localhost:3000
(von einem anderen Gerät im selben Netz:  http://IP-DES-RECHNERS:3000)

Beim allerersten Start wird automatisch ein Owner-Account angelegt:

   Benutzername:  was bei DASHBOARD_OWNER steht (leer gelassen: admin)
   Passwort:      das, was du bei DASHBOARD_PASSWORD eingetragen hast

DASHBOARD_OWNER zählt nur beim allerersten Start. Willst du den Namen später
ändern: Programm beenden, in users.json bei  "username": "admin"  den Namen
ändern (die Anführungszeichen behalten), speichern und neu starten.

WICHTIG: Lass DASHBOARD_PASSWORD danach in der .env stehen. Ist die Zeile
leer oder gelöscht, schaltet sich der Login komplett ab und das Dashboard ist
für jeden offen. Geprüft wird das Passwort ab dem ersten Start nur noch gegen
users.json - eine spätere Änderung in der .env ändert es nicht.

Dein eigenes Passwort änderst du in der Verwaltung unter "Mein Passwort
ändern", die von Admins und Usern ebenfalls dort (Abschnitt 6).
Owner-Passwort vergessen: DASHBOARD_PASSWORD in der .env ändern, users.json
UND users.backup.json löschen, neu starten. Der Owner wird neu angelegt, alle
anderen Benutzer sind dann weg.


------------------------------------------------------------------------------
 5. ACCOUNTS HINZUFÜGEN UND ANMELDEN
------------------------------------------------------------------------------

Java-Account:
   Im Dashboard links bei "Account hinzufügen" den Minecraft-Namen eingeben
   und auf "Hinzufügen" klicken.

Bedrock-Account:
   Ein Punkt vor den Namen setzen, z.B.  .MeinGamertag
   Der Punkt sagt dem Manager "Bedrock". Beim Login-Code das Microsoft-Konto
   nehmen, das zu diesem Xbox-Gamertag gehört.

Microsoft-Login (nur beim ersten Mal pro Account):
   1. Der Account startet, im Dashboard erscheint oben eine Box mit einem Code
      und einem Link (und eine Nachricht in Discord, falls eingerichtet).
   2. Klick in Discord auf "Jetzt anmelden" oder auf "Hier klicken und
      anmelden" (im Dashboard ebenso). Der Code steckt schon im Link
      (https://www.microsoft.com/link?otc=CODE), du musst nichts kopieren.
      Fragt die Seite doch nach dem Code, steht er zum Kopieren darunter.
   3. Melde dich mit dem Microsoft-Konto an, das zu DIESEM Minecraft-Account
      gehört.
   4. Der Code gilt so lange, wie in der Nachricht steht (meist 15 Minuten).
      Danach ist der Login gespeichert und es ist kein Code mehr nötig. Die
      Discord-Nachricht ändert sich dann auf "ist angemeldet".
   Läuft ein Code ab, kommt automatisch ein neuer (die alte Nachricht wird als
   "abgelaufen" markiert, nur der neueste Code gilt). Nach 4 unbenutzten Codes
   pausiert der Login für diesen Account, bis du auf Start drückst (im
   Dashboard oder über den Knopf in Discord).
   Der Login-Token liegt im Ordner "nmp-cache" im Minecraft-Ordner:
      Windows:  %APPDATA%\.minecraft\nmp-cache
      Linux:    ~/.minecraft/nmp-cache
      Mac:      ~/Library/Application Support/minecraft/nmp-cache
   Dieser Ordner ist so sensibel wie ein Passwort - niemals weitergeben.

Buttons pro Account:
   Start / Stop       Account starten / stoppen
   ★                  Diesen Account zur Chat-Quelle machen
   ✏️                  Umbenennen (der gespeicherte Login bleibt erhalten)
   ⚙️                  Auto-Chat: Text oder Befehl plus Sekunden nach dem
                      Verbinden, wird nach jedem Reconnect automatisch gesendet
   🔔 / 🔕            Discord-Meldung "anderswo eingeloggt" an/aus (nur Java).
                      Neu hinzugefügte Accounts starten mit 🔕 (aus);
                      bestehende Accounts behalten ihre Einstellung.
   ✕                  Account entfernen (löscht auch den gespeicherten Login)

Gut zu wissen:
 - Loggst du dich mit einem Account selbst im Spiel ein, fliegt der Bot raus
   ("anderswo eingeloggt"). Er verbindet sich dann bewusst NICHT automatisch
   neu. Drücke wieder auf Start, wenn du fertig bist.
 - Beim Programmstart werden alle gespeicherten Accounts automatisch gestartet.
 - Bedrock-Accounts bleiben online und können Nachrichten und /Befehle senden:
   im Dashboard-Chat (Auswahl "Name (Bedrock)"), per Discord (!mc) und per
   Auto-Chat. Normaler Chat geht auf jeder Bedrock-Version, /Befehle nur
   auf Servern ab Bedrock 1.26 (sonst kommt eine Fehlermeldung). Nicht möglich
   sind: Chat-Quelle sein, Ingame-Steuerung (WASD usw.) und die Tab-Taste zur
   Vervollständigung. Antworten auf Befehle siehst du nur, wenn sie im Chat des
   Servers erscheinen.
 - Rechts im Dashboard: Live-Chat (über den gewählten Account schreiben) und
   eine Steuerung (Laufen, Springen, Schleichen, Klicks, Hotbar, Droppen).


------------------------------------------------------------------------------
 5b. MEHRERE SERVER (OPTIONAL)
------------------------------------------------------------------------------

Ein Account kann zusätzlich auf weiteren Servern online sein, z.B. auf
clashsmp.de UND auf deinem eigenen Server. Wer das nicht nutzt, merkt davon
nichts: Alle Accounts laufen wie immer auf dem Standardserver aus der .env.

Server anlegen (Owner und Admins):
   Verwaltung -> Karte "Server" -> "+ Server hinzufügen":
      Name          z.B. Lobby (so heißt er im Dashboard und in Discord)
      Kürzel        für Discord, z.B. lobby  ->  !start NilsMovie@lobby
                    (leer lassen = wird aus dem Namen gebildet, bleibt fest)
      Adresse       ohne Port, z.B. play.beispiel.net oder 192.168.1.20
      Java-Port     leer = auf diesem Server keine Java-Accounts
      Bedrock-Port  leer = auf diesem Server keine Bedrock-Accounts
   Derselbe Server (gleiche Adresse und gleicher Port) lässt sich nicht
   zweimal eintragen - der Account würde sich sonst selbst rauswerfen.
   Auto-Chat-Vorlage: Befehle, die jede NEUE Verbindung zu diesem Server als
   Auto-Chat bekommt (beim Standardserver: jeder neue Account). Bestehende
   bleiben unverändert.
   Den Standardserver änderst du nur in der .env.

Account auf einen weiteren Server schicken:
   Dashboard -> beim Account "+ Server" -> Server wählen -> "Hinzufügen und
   starten". Unter dem Account erscheint eine Zeile "↳ Servername" mit eigenem
   Status, Start/Stop, Online-Zeit, ★ (Chat-Quelle für diesen Server), 🔔,
   ⚙️ (eigener Auto-Chat) und ✕ (vom Server entfernen - auf dem Standardserver
   bleibt der Account).
   Wie beim ersten Join auf dem Standardserver kommt der Auto-Chat erst ab dem
   zweiten Einloggen auf DIESEM Server.

Was wo gilt:
   Pro Account       Microsoft-Login (kein zweiter Code), Rechte der User
                     (wer einen Account bedienen darf, darf es auf allen Servern)
   Pro Verbindung    Status, Auto-Chat, Glocke, Online-Zeit, Reconnect
   Pro Server        Chat und Chat-Quelle, Kick-Sammelmeldungen,
                     "Alle offline/online", Bedrock-Pause
   Für alle          Die Warteschlange: es verbindet sich immer nur EINE
                     Verbindung gleichzeitig, über alle Server. Wartet ein
                     Account auf seinen Login-Code, warten seine anderen
                     Verbindungen, bis er angemeldet ist.

Chat: Oben im Chat-Fenster wählst du, von welchem Server du den Chat siehst
(die Auswahl erscheint erst, wenn es weitere Server mit Java-Accounts gibt).
Gesendet wird über einen Account auf diesem Server. Der Discord-Chat-Kanal
und Erweiterungen bekommen weiterhin nur den Chat vom Standardserver.

Discord: An den Accountnamen "@kürzel" hängen (oder den Servernamen):
   !start NilsMovie@lobby      !stop NilsMovie@alle (auf allen Servern)
   !mc NilsMovie@lobby hallo   !primary NilsMovie@lobby
   !add NilsMovie@lobby        (bestehenden Account zusätzlich dorthin)
Ohne @ gilt wie bisher der Standardserver. Meldungen nennen den Server, z.B.
"NilsMovie (Lobby) ist anderswo eingeloggt".

Schalter in der .env:
   MULTI_SERVER_JAVA=0         Java auf weiteren Servern aus (Standard: an)
   MULTI_SERVER_BEDROCK=1      Bedrock auf weiteren Servern an (Standard: aus)
   MULTI_SERVER_BEDROCK_MAX=2  höchstens so viele Bedrock-Verbindungen zu
                               weiteren Servern (Standard 2)
   Ist ein Schalter aus, ruhen die schon angelegten Verbindungen (Status sagt
   warum) und es lassen sich keine neuen anlegen.

Bedrock auf weiteren Servern zuerst testen:
   Jede Bedrock-Verbindung läuft in einem eigenen Thread (ca. 80 MB RAM, bei
   vielen Entities spürbar CPU). Nimm für den ersten Test einen Ersatz-Account,
   lass es 30 Minuten laufen und vergleiche die Diagnose-Zeilen vorher/nachher:
      sudo journalctl -u afk-manager --since "30 min ago" | grep "Diagnose\] RAM"
   Kommt "anderswo eingeloggt", gehören die beiden Server zum selben Netzwerk
   (z.B. Unterserver hinter demselben Proxy) - dann geht das nicht.
   Die Bedrock-Pause gilt pro Server: nimmt der zweite Server gerade keine
   Bedrock-Verbindungen an, warten nur die Accounts dort.

Update und Zurück:
   Beim ersten Start der Mehrserver-Version legt der Manager einmalig
   accounts.vor-mehrserver.json an (unveränderte Kopie). accounts.json behält
   ihr altes Format, die weiteren Server stehen in eigenen Dateien
   (servers.json, verbindungen.json), die ältere Versionen einfach ignorieren.
   Zurück zur älteren Version geht also jederzeit (Abschnitt 8) - die Accounts
   laufen dann wieder nur auf dem Standardserver, ohne neuen Login.


------------------------------------------------------------------------------
 6. BENUTZER UND ROLLEN
------------------------------------------------------------------------------

Oben rechts im Dashboard gibt es für Owner und Admins den Button "Verwaltung".

   Owner   Darf alles, inklusive Admins anlegen und löschen.
   Admin   Sieht alle Accounts, darf normale Benutzer anlegen, löschen und
           ihnen Accounts zuweisen, Server anlegen (Abschnitt 5b). Admins und
           Owner kann er nicht ändern.
   User    Sieht und bedient nur die zugewiesenen Minecraft-Accounts: Start/Stop,
           Chat und Steuerung. Kein Hinzufügen, Umbenennen oder Entfernen.

So kannst du Freunden Zugriff auf einzelne Accounts geben, ohne dass sie alles
sehen.


------------------------------------------------------------------------------
 7. DISCORD (OPTIONAL)
------------------------------------------------------------------------------

Alles hier ist freiwillig. Ohne Discord läuft das Dashboard normal.

Discord-IDs kopieren: Discord > Einstellungen > Erweitert > "Entwicklermodus"
einschalten. Dann Rechtsklick auf Kanal oder Rolle > "ID kopieren".

a) Webhooks (nur Nachrichten senden):
   Kanal bearbeiten > Integrationen > Webhooks > Neuer Webhook > URL kopieren.
   DISCORD_WEBHOOK_URL         Benachrichtigungen: Kicks, alle offline/online,
                               Login-Codes, Tageszusammenfassung um 00:00 Uhr.
                               (Mit Bot: nur noch Rückfall, siehe b.)
   DISCORD_CHAT_WEBHOOK_URL    Spiegelt den Ingame-Chat (am besten eigener Kanal).

b) Bot (für Befehle und Buttons):
   1. https://discord.com/developers/applications > "New Application".
   2. Reiter "Bot": Token kopieren > DISCORD_BOT_TOKEN.
   3. Auf derselben Seite unter "Privileged Gateway Intents" den
      "Message Content Intent" einschalten. Ohne ihn liest der Bot keine Befehle.
   4. Reiter "OAuth2" > "URL Generator": Scope "bot" ankreuzen. Rechte: Kanäle
      ansehen, Nachrichten senden, Links einbetten, Nachrichtenverlauf lesen.
      Die erzeugte URL im Browser öffnen und den Bot zu deinem Server einladen.
   5. ID des Kanals, in dem der Bot arbeiten soll > DISCORD_CHANNEL_ID.
   6. Bot-Token UND Kanal-ID müssen beide gesetzt sein.

   Ist der Bot eingerichtet, schickt ER alle Meldungen (Login-Codes, Kicks,
   online/offline, Start, Tageszusammenfassung, Chat-Spiegel), und zwar in
   dieselben Kanäle, in die bisher die Webhooks geschrieben haben. Die Webhooks
   bleiben nur als Rückfall eingetragen (falls der Bot mal nicht verbunden ist).
   Der Bot braucht dafür in diesen Kanälen ebenfalls die Rechte aus Punkt 4.
   Wer die Kanäle fest vorgeben will (optional):
      DISCORD_NOTIFY_CHANNEL_ID   Kanal für alle Meldungen
      DISCORD_CHAT_CHANNEL_ID     Kanal für den Chat-Spiegel

   DISCORD_ALLOWED_ROLE_IDS: Rollen-IDs mit Komma getrennt, die Befehle nutzen
   dürfen. Bleibt das leer, darf JEDER mit Zugriff auf den Kanal die Befehle
   benutzen. Halte den Kanal dann privat oder trage Rollen ein.

   Befehle im Bot-Kanal:
      !mc Account Text          Text oder /Befehl über den Account senden
      !start Account | all      Account (oder alle, auf allen Servern) starten
      !stop Account | all       Account (oder alle, auf allen Servern) stoppen
      !list                     Status aller Accounts (weitere Server eingerückt)
      !primary Account          Chat-Quelle festlegen
      !rename Alt Neu           Account umbenennen
      !add Name                 Account hinzufügen
   Weitere Server: Account@kürzel bzw. Account@alle (siehe Abschnitt 5b).

   "Alle Accounts wieder online" kommt nur nach einem echten Ausfall: nach
   "Alle offline", nach einem Server-Neustart (Massen-Kick), nach dem Start des
   Managers oder wenn ein Account länger als 10 Minuten weg war. Fliegt nur ein
   Account kurz raus und ist gleich wieder da, kommt keine Meldung.
   Einstellbar: DISCORD_ALL_ONLINE_AFTER_MIN=10 in der .env.

   Klappt ein Klick auf einen Discord-Knopf nicht, steht der Grund im Log
   (Zeile mit [Diagnose]): "kam zu spät an" = Programm war ausgelastet, einfach
   nochmal; "von einer ANDEREN Instanz beantwortet" = der AFK-Manager läuft doppelt.

Nach Änderungen an der .env das Programm neu starten.


------------------------------------------------------------------------------
 8. DAUERBETRIEB UND WARTUNG
------------------------------------------------------------------------------

Damit der Manager nach dem Schließen des Terminals und nach einem Neustart des
Rechners weiterläuft, nimm pm2:

   npm install -g pm2
   pm2 start server.js --name afk-manager
   pm2 save
   pm2 startup              (Linux/Mac: zeigt einen Befehl an, den du kopieren
                             und ausführen musst)

Auf Linux geht statt pm2 auch ein systemd-Dienst (siehe README.md). Nimm
nur EINES von beiden, sonst läuft der Manager doppelt. Mit systemd heißen die
Befehle: sudo systemctl restart afk-manager / sudo journalctl -u afk-manager -f

Nützlich:
   pm2 logs afk-manager      Logs live ansehen
   pm2 restart afk-manager   Neu starten (nach .env- oder Datei-Änderungen)
   pm2 stop afk-manager      Stoppen

Logs begrenzen (empfohlen, sonst wachsen sie ohne Ende):

   pm2 install pm2-logrotate
   pm2 set pm2-logrotate:max_size 50M
   pm2 set pm2-logrotate:retain 3
   pm2 set pm2-logrotate:compress true

Nur Linux, dringend empfohlen: Core-Dumps ausschalten. Stürzt ein Prozess ab,
schreibt Linux sonst ein Speicherabbild von mehreren hundert MB in den
Projektordner (Dateien "core.12345"). Auf einem Raspberry Pi hat sich das schon
auf rund 19 GB summiert und die Speicherkarte gefüllt.

   echo "kernel.core_pattern=/dev/null" | sudo tee -a /etc/sysctl.conf
   sudo sysctl -p

Updates einspielen (im Ordner afk-manager):

   git pull
   npm install
   danach neu starten (pm2 restart afk-manager bzw. sudo systemctl restart afk-manager)

Macht ein Update Probleme, zurück auf die vorige Version:
   git log --oneline          Versionen ansehen
   git checkout <nummer>      z.B. git checkout a1b2c3d
   neu starten wie oben; später mit  git checkout main  wieder auf den neuesten Stand.
Was sich in einer Version geändert hat, steht in CHANGELOG.md.

Deine .env, accounts.json und users.json bleiben dabei unverändert. Ändere die
Programmdateien nicht selbst, sonst bricht "git pull" ab.

Sichern: Kopiere ab und zu accounts.json, users.json, deine .env und den
nmp-cache-Ordner an einen sicheren, privaten Ort (nicht in die Cloud-Freigabe!).


------------------------------------------------------------------------------
 9. SICHERHEIT
------------------------------------------------------------------------------

 - Setze IMMER ein DASHBOARD_PASSWORD. Ohne Passwort hat jeder, der die Seite
   erreicht, vollen Zugriff.
 - Das Dashboard läuft über unverschlüsseltes HTTP. Mach es nicht einfach per
   Port-Weiterleitung im Internet erreichbar, Passwort und Login-Cookie wären
   mitlesbar. Für den Zugriff von außen nimm HTTPS, z.B. über einen
   Cloudflare Tunnel, ein VPN oder einen Reverse-Proxy.
 - NIEMALS weitergeben oder hochladen: .env, accounts.json, users.json,
   die *.backup.json-Dateien, den nmp-cache-Ordner, Logs und core.*-Dateien.
   Darin stehen Passwort-Hashes, Discord-Token, Webhook-URLs und die
   Microsoft-Logins deiner Accounts.
 - Ist ein Discord-Bot-Token oder eine Webhook-URL versehentlich öffentlich
   geworden: sofort im Discord Developer Portal bzw. in den Kanal-Einstellungen
   neu erzeugen. Die alte Version ist dann wertlos.
 - Nutze nur eigene Accounts und prüfe, ob dein Minecraft-Server AFK-Accounts
   erlaubt. Die Nutzung geschieht auf eigene Verantwortung.


------------------------------------------------------------------------------
 10. PROBLEME UND LÖSUNGEN
------------------------------------------------------------------------------

Dashboard nicht erreichbar
   pm2 logs afk-manager  (oder die Ausgabe im Terminal) ansehen. Läuft das
   Programm? Stimmt der PORT? Blockiert eine Firewall den Port?

Login-Code funktioniert nicht / "device_code has already been used"
   1. Zwei-Faktor-Authentifizierung beim Microsoft-Konto aktivieren
      (Abschnitt 0). Das hat in den bisherigen Fällen geholfen.
   2. Prüfen, ob der Speicherplatz voll ist (siehe "ENOSPC").

"ENOSPC: no space left on device"
   Die Festplatte ist voll. Mit  df -h  prüfen (Linux). Häufige Ursachen:
   riesige pm2-Logs (pm2 flush) oder core.*-Dateien im Projektordner
   (rm core.*). Siehe Abschnitt 8 für die dauerhafte Lösung.

npm install bricht ab (raknet-native)
   Das gehört zur Bedrock-Unterstützung und braucht Build-Werkzeuge.
   Linux/Raspberry Pi:   sudo apt install -y build-essential cmake
   Danach "npm install" wiederholen. Auf Windows sind die Visual Studio
   Build Tools plus CMake nötig.
   Brauchst du kein Bedrock: Lösche in package.json die Zeile mit
      "bedrock-protocol"
   (sie steht oben unter "dependencies", alle anderen Zeilen bleiben
   unverändert) und führe "npm install" erneut aus. Java-Accounts
   funktionieren dann normal. Im Log erscheint danach beim Start einmalig
   "bedrock-protocol nicht verfuegbar" - das ist in diesem Fall korrekt.

Im Log: "bedrock-protocol nicht verfuegbar"
   Das Paket ist nicht installiert oder konnte nicht geladen werden. Siehe
   den Punkt direkt darüber. Java-Accounts sind nicht betroffen.

Bedrock-Account bricht ständig ab, Log: "Invalid tag: 103 > 20"
   Das ist ein Fehler in einer Bibliothek (prismarine-nbt), der beim Lesen
   bestimmter Pakete auftritt. Seit dem Paketfilter (siehe "Weniger Rechenlast
   bei Bedrock") liest der Manager die meisten Pakete gar nicht mehr, deshalb
   sollte das kaum noch vorkommen. Lass MC_BEDROCK_PACKET_FILTER eingeschaltet.

Mehr als ca. 10 Bedrock-Accounts gleichzeitig: weitere bekommen "Connect timed
out"
   In einem Heimnetz wurde das beobachtet. Der Server-Owner hat bestätigt, dass
   serverseitig kein Limit eingestellt ist, die Ursache blieb ungeklärt (auf
   dem Heimnetz-Anschluss trat es auf, über einen Handy-Hotspot nicht). Falls
   es bei dir auch passiert, ist es kein Fehler im Programm.

Discord-Bot reagiert nicht
   Sind DISCORD_BOT_TOKEN und DISCORD_CHANNEL_ID beide gesetzt? Ist der
   "Message Content Intent" eingeschaltet? Darf der Bot im Kanal lesen und
   schreiben? Wurde das Programm nach der .env-Änderung neu gestartet?

Bedrock-Accounts und NetherNet (seit Bedrock 26.60, Okt. 2026)
   Bedrock 26.60 verbindet sich nicht mehr über RakNet, sondern über NetherNet
   (Anmeldung per HTTP auf dem Bedrock-Port, danach WebRTC über UDP). Geyser
   nimmt nach dem Update standardmäßig nur noch NetherNet an.
   Der Manager kann beides: Vor dem Verbinden fragt er den Server, ob er
   NetherNet anbietet (wird 10 Minuten gemerkt), und nimmt sonst RakNet.
   Im Log steht dazu einmal:
      [Bedrock] clashsmp.de:19132 bietet NetherNet an - ... über NetherNet
   und je Account:  --- eingeloggt (Bedrock, NetherNet) ---
   Optional in der .env:
      MC_BEDROCK_TRANSPORT=auto        auto (Standard), nethernet oder raknet
      MC_BEDROCK_VERSION=1.26.60       feste Version (leer = neueste bekannte)
      MC_BEDROCK_NETHERNET_IPV6=1      NetherNet über IPv4 und IPv6 (Standard: nur IPv4)
      MC_BEDROCK_NETHERNET_IPV6=only   NetherNet NUR über IPv6 (siehe unten)
      MC_BEDROCK_NETHERNET_WEBRTC=werift  empfohlen (siehe "Eigene Threads" unten)
   WebRTC-Umsetzung: werift (reines JavaScript) läuft für jeden Bedrock-Account in
   einem eigenen Thread. Das native WebRTC (wrtc, Paket @roamhq/wrtc) läuft nur
   im Haupt-Thread und hat dort am 31.10.2026 in 5 Minuten 5 GB RAM verbraucht und
   den Manager bis zu 30 s einfrieren lassen - nicht benutzen.
   Bietet der Server zusätzlich RakNet an (Geyser "transport: both"), nimmt der
   Manager im Modus auto automatisch RakNet (bewährt, nativer Code).
   Geyser beendet eine Verbindung, wenn für einen Spieler mehr als 64 MiB im
   Ausgang warten (der Client nimmt nicht schnell genug ab) - im Log steht dann
   bei "NetherNet getrennt" ein "SCTP-ABORT vom Server".
   Warum nur IPv4: Mit IPv6 antwortete der Server teils über IPv6, während die
   Bots über IPv4 sendeten. Die IPv6-Firewall der FritzBox hat die Antworten dann
   nach 2-4 Minuten nicht mehr durchgelassen, die Accounts flogen ständig raus.
   Nur IPv6 (MC_BEDROCK_NETHERNET_IPV6=only): Seit 31.10.2026 antwortet clashsmp.de
   über IPv4 nicht mehr auf NetherNet (auch nicht nach neuer IP), über IPv6 schon.
   Mit "only" laufen beide Richtungen über IPv6 - das Gemisch aus beidem war die
   Ursache der Abbrüche oben. Im Log steht dann "NetherNet ueber nur IPv6" und je
   Account "--- eingeloggt (Bedrock, NetherNet ueber IPv6) ---".
   Antwortet der Server irgendwann wieder über IPv4: Zeile aus der .env löschen
   und neu starten.
   Reißt eine NetherNet-Verbindung ab, steht im Log eine Zeile
      [Diagnose] [Account] NetherNet getrennt nach ... min - Verlauf: ...
   ("ICE failed" = unsere Seite hat aufgegeben, sonst hat der Server getrennt).
   Braucht bedrock-protocol 3.61.0 oder neuer und die Datei nethernet-http.js
   im Programmordner.
   Kommt trotzdem keine Verbindung zustande, versuchen es die Accounts von
   selbst weiter (Pause wächst bis 5 Minuten) und blockieren die anderen
   Accounts nicht. Kommt kein Bedrock-Account durch, schickt der Manager einmal
   (höchstens alle 6 Stunden) eine Meldung mit dem Grund in Discord.

Schutz gegen Dauer-Neuverbindungen (Bedrock)
   Hunderte Neuverbindungen pro Nacht können dazu führen, dass der Server bzw.
   sein DDoS-Schutz unsere IP eine Weile sperrt. Deshalb:
    - Bedrock-Pause: Scheitern 5 Verbindungsversuche hintereinander und ist KEIN
      Bedrock-Account online, warten alle Bedrock-Accounts 15 Minuten (gilt pro
      Server - bei mehreren Servern nur die Accounts auf dem betroffenen Server)
      (Status "Bedrock-Pause bis HH:MM"). Danach probiert es EIN Account. Klappt
      es, kommen die anderen der Reihe nach; sonst wieder 15 Minuten Pause.
      Log:  [Bedrock] 5 Verbindungsversuche hintereinander gescheitert ...
    - Bricht die Verbindung eines Accounts immer wieder kurz nach dem Einloggen
      ab (unter 5 Minuten), wartet er ab dem 3. Mal in Folge 5 Minuten, ab dem
      5. Mal 15 Minuten. Status "Bricht immer wieder ab – Pause bis HH:MM".
    - Ein Klick auf Start (Webseite oder Discord) probiert es immer sofort.
    - Scheitert der Aufbau, steht der Grund im Log, z.B.
         [Diagnose] [Account] NetherNet-Aufbau gescheitert (connecterror:9) - Verlauf: ...
      "ICE checking" ohne "ICE connected" = über UDP kam gar nichts zurück.
   Einstellbar in der .env (meist nicht nötig):
      MC_BEDROCK_PAUSE_AFTER_FAILS=5   ab so vielen Fehlschlägen in Folge Pause
      MC_BEDROCK_PAUSE_MIN=15          Länge der Pause in Minuten

Weniger Rechenlast bei Bedrock
   Ein AFK-Bot braucht von den 800-1500 Paketen pro Sekunde, die der Server
   schickt, nur eine Handvoll. Der Rest wird am Paketkopf erkannt und
   weggeworfen, statt ihn zu entschlüsseln. Dazu wird schneller entpackt, und
   (bei werift) wird nur noch jedes 2. Datenpaket einzeln bestätigt statt jedes.
   Im Log beim Start:
      [Bedrock] Paketfilter an (1.26.60): 9 von 254 Pakettypen werden gelesen ...
   Alle 10 Minuten zeigt die Diagnose-Zeile CPU und die Pakete pro Sekunde:
      [Diagnose] RAM ... CPU 35%, 18 Bots verbunden, Bedrock-Pakete/s gelesen 3, verworfen 4200
   (CPU 100% = ein Prozessorkern voll. Durch die eigenen Threads kann der Wert
   über 100% liegen - das ist in Ordnung. Ein Warnzeichen ist "Prozess hing bis
   zu ... ms" mit Werten über 1000: dann ist der Haupt-Thread überlastet.)
   Abschalten, falls je etwas komisch ist: MC_BEDROCK_PACKET_FILTER=0 bzw.
   MC_BEDROCK_FAST_INFLATE=0 in der .env.

Eigene Threads für Bedrock-Accounts
   Accounts an einer Farm bekommen über NetherNet mehrere tausend Nachrichten pro
   Sekunde (einer über 4000). Jede muss entschlüsselt und bestätigt werden.
   Lief alles in einem Thread, war ein Kern voll (top: 105%), die Bestätigungen
   kamen zu spät, und Geyser hat nach 2-3 Minuten getrennt (SCTP-ABORT).
   Deshalb läuft jeder NetherNet-Account in einem eigenen Thread (Dateien
   bedrock-worker.js, bedrock-thread.js, bedrock-tuning.js) und damit auf einem
   eigenen Kern. Webseite, Discord und Java-Bots bleiben im Haupt-Thread frei.
   Im Log:  [Bedrock] NetherNet-WebRTC: werift, jeder Bedrock-Account in einem eigenen Thread
   Kostet etwa 80 MB RAM pro Bedrock-Account. RakNet-Accounts laufen wie bisher
   im Haupt-Thread. Abschalten: MC_BEDROCK_THREADS=0

Protokoll: wer hat was gemacht (Webseite und Discord)
   Jede Aktion wird mit Uhrzeit festgehalten:
    - Webseite: Anmeldung (auch fehlgeschlagene), Abmeldung, Accounts anlegen,
      löschen, umbenennen, starten, stoppen, Chat/Befehle, Stern, Glocke,
      Auto-Chat, Benutzer anlegen/ändern/löschen, Passwortänderungen, Server
      und Verbindungen anlegen/ändern/entfernen (mit Server, z.B.
      "NilsMovie@lobby") - jeweils mit Benutzer, IP-Adresse und Gerät
      (z.B. "iPhone / Safari").
    - Discord: alle !-Befehle, Start-Knöpfe, Chat über !mc - jeweils mit
      Discord-Name, Discord-ID und Kanal. Auch abgelehnte Versuche ohne
      Berechtigung.
   Nachschauen (nur der Owner - Admins sehen das Protokoll nicht):
    - Dashboard -> Verwaltung -> "Protokoll" (Suche nach Name, Account, IP ...)
    - oder:  tail -n 50 ~/afk-manager/audit.log
    - oder:  sudo journalctl -u afk-manager --no-pager | grep "\[Protokoll\]"
   Die Datei audit.log wird ab 5 MB zu audit.log.1 (davor liegende Einträge
   bleiben also lange erhalten).
   In Discord kommt standardmäßig NICHTS davon. Wer es doch will:
   AUDIT_DISCORD=1 in der .env - dann meldet der Manager sofort in Discord:
   Anmeldung von einer für den Benutzer neuen IP-Adresse, Account im Dashboard
   angelegt/gelöscht/umbenannt, Benutzer angelegt/gelöscht/Passwort/Rolle geändert.

Aktive Anmeldungen und Passwort
   Dashboard -> Verwaltung -> "Aktive Anmeldungen" (nur für den Owner) zeigt jedes
   angemeldete Gerät mit IP-Adresse und wann es zuletzt aktiv war. Fremde Geräte
   lassen sich dort einzeln abmelden, oder alle anderen auf einmal.
   "Mein Passwort ändern" geht für jeden (auch Owner und Admin) und meldet
   alle anderen Geräte dieses Benutzers ab. Passwörter brauchen mindestens 8
   Zeichen. Ein Neustart des Managers meldet ALLE Geräte ab.
   Account- und Benutzernamen dürfen keine Sonderzeichen wie < > " ' enthalten
   (sonst könnte darüber Code im Dashboard ausgeführt werden).

Discord-Klicks klappen nur manchmal / Antworten kommen doppelt
   Meist läuft der AFK-Manager zweimal mit demselben Bot-Token (z.B. auf zwei
   Rechnern oder per pm2 UND systemd). Dann antworten beide auf jeden Klick und
   es gewinnt zufällig einer. Auf demselben Rechner bleibt eine zweite Instanz
   still, weil ihr Port schon belegt ist (Log: "[Diagnose] Port ... ist schon
   belegt"). Prüfen:  pm2 list  und  sudo systemctl status afk-manager

 11. HINWEIS: AUF CLASHSMP.DE ZUGESCHNITTEN

Der AFK Manager wurde für den Server clashsmp.de gebaut. Die Grundfunktionen
laufen auf jedem Minecraft-Server. Folgendes ist aber auf clashsmp.de
zugeschnitten und sieht woanders evtl. anders aus:
 - Die Formatierung der Chat-Spiegelung in Discord (Rang-Tags wie "[Spieler]",
   Shop- und Tipp-Nachrichten).
 - In der .env.example ist clashsmp.de als Standardserver eingetragen (im
   Programm selbst ist kein Server fest eingebaut).
